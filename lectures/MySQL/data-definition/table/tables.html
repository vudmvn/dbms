1. Mục tiêu học tập

Sinh viên có thể tạo một schema nhỏ và thay đổi nó an toàn: thêm/xóa cột, đổi tên, đổi kiểu dữ liệu, quản lý constraints, làm rỗng hoặc xóa bảng.

Tạo

CREATE DATABASE, CREATE TABLE.

Thay đổi

ALTER TABLE và các clauses.

Xóa / đổi tên

RENAME, TRUNCATE, DROP.

An toàn

Kiểm tra dữ liệu và dependency trước DDL.

2. DDL là gì?

DDL – Data Definition Language dùng để định nghĩa hoặc thay đổi database objects: database, table, column, constraint, index, view…

CREATE

Tạo object.

ALTER

Sửa structure.

TRUNCATE

Xóa mọi rows, giữ table.

DROP

Xóa object.

DELETE là DML, không phải DDL: nó tác động rows nhưng không thay định nghĩa table.

4. CREATE TABLE

CREATE TABLE định nghĩa một table mới với columns, data types và constraints.

CREATE TABLE student (
    student_id INT,
    full_name  VARCHAR(100),
    email      VARCHAR(200),
    dob        DATE,
    gpa        DECIMAL(3,2)
);
NhómVí dụ typeỨng dụng
IntegerINT, BIGINTID, quantity
Exact numericDECIMAL(p,s)Price, GPA
StringCHAR, VARCHAR, TEXTName, code
Date/timeDATE, DATETIME, TIMESTAMPDOB, created_at

Thực hành 2

Tạo PRODUCT(ProductID, ProductName, Price, Stock, CreatedAt).

Gợi ý
CREATE TABLE product (
  product_id INT,
  product_name VARCHAR(150),
  price DECIMAL(12,2),
  stock INT,
  created_at DATETIME
);

5. Constraints trong CREATE TABLE

CREATE TABLE department (
    department_id INT PRIMARY KEY,
    department_code VARCHAR(20) UNIQUE NOT NULL,
    department_name VARCHAR(100) NOT NULL
);

CREATE TABLE student (
    student_id INT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(200) UNIQUE NOT NULL,
    gpa DECIMAL(3,2) CHECK (gpa BETWEEN 0 AND 4),
    department_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_student_department
      FOREIGN KEY (department_id)
      REFERENCES department(department_id)
);
ConstraintÝ nghĩa
PRIMARY KEYIdentifier chính
FOREIGN KEYReferential integrity
UNIQUEKhông duplicate
NOT NULLBắt buộc có giá trị
CHECKPhải thỏa điều kiện
DEFAULTGiá trị mặc định

Thực hành 3

Tạo COURSE với CourseID PK, CourseCode UNIQUE NOT NULL, CourseName NOT NULL, Credits từ 1 đến 6.

Đáp án
CREATE TABLE course (
  course_id INT PRIMARY KEY,
  course_code VARCHAR(20) UNIQUE NOT NULL,
  course_name VARCHAR(150) NOT NULL,
  credits INT CHECK (credits BETWEEN 1 AND 6)
);

7. ALTER TABLE

ALTER TABLE sửa cấu trúc table hiện có: thêm/xóa columns, thay type, rename, thêm/xóa indexes và constraints.

8. ADD COLUMN

ALTER TABLE student
ADD COLUMN phone VARCHAR(20);

ALTER TABLE student
ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE';

MySQL còn hỗ trợ vị trí:

ALTER TABLE student ADD COLUMN gender VARCHAR(20) AFTER full_name;
ALTER TABLE student ADD COLUMN row_no INT FIRST;

Thực hành 4

Thêm Phone, Status mặc định ACTIVE và UpdatedAt cho PRODUCT.

Đáp án
ALTER TABLE product ADD COLUMN phone VARCHAR(20);
ALTER TABLE product ADD COLUMN status VARCHAR(20) DEFAULT 'ACTIVE';
ALTER TABLE product ADD COLUMN updated_at DATETIME;

9. DROP COLUMN

ALTER TABLE student
DROP COLUMN phone;
DROP COLUMN làm mất dữ liệu của cột. Trước production migration, kiểm tra views, code, reports, ETL và dependencies.

Thực hành 5

Xóa column legacy_code.

Đáp án
ALTER TABLE student DROP COLUMN legacy_code;

10. RENAME COLUMN

ALTER TABLE student
RENAME COLUMN full_name TO student_name;

Trong MySQL hiện đại, RENAME COLUMN đổi tên mà không cần lặp lại datatype.

Ứng dụng, views hoặc stored code dùng tên cũ có thể cần sửa riêng.

Thực hành 6

Đổi student_name về full_name.

Đáp án
ALTER TABLE student
RENAME COLUMN student_name TO full_name;

11. MODIFY và CHANGE COLUMN trong MySQL

MODIFY — đổi definition, giữ tên

ALTER TABLE student
MODIFY COLUMN full_name VARCHAR(200) NOT NULL;

CHANGE — đổi tên và/hoặc definition

ALTER TABLE student
CHANGE COLUMN full_name student_name VARCHAR(200) NOT NULL;
Phải khai báo lại các thuộc tính muốn giữ như NOT NULL, DEFAULT khi dùng MODIFY/CHANGE.

Thực hành 7

Đổi price thành DECIMAL(14,2) NOT NULL.

Đáp án
ALTER TABLE product
MODIFY COLUMN price DECIMAL(14,2) NOT NULL;

12. DEFAULT và NOT NULL

ALTER TABLE student
ALTER COLUMN status SET DEFAULT 'ACTIVE';

ALTER TABLE student
ALTER COLUMN status DROP DEFAULT;

Trong MySQL, đổi kiểu/nullability thường dùng MODIFY:

ALTER TABLE student
MODIFY COLUMN email VARCHAR(200) NOT NULL;
Nếu dữ liệu hiện có chứa NULL, thêm NOT NULL có thể thất bại.

Thực hành 8

Đặt Product.stock NOT NULL DEFAULT 0.

Đáp án
ALTER TABLE product
MODIFY COLUMN stock INT NOT NULL DEFAULT 0;

ALTER TABLE student

CHECK (gpa BETWEEN 0 AND 4);

REFERENCES department(department_id);

Thêm FK Product.SupplierID → Supplier.SupplierID, tên fk_product_supplier.

FOREIGN KEY (supplier_id)
REFERENCES supplier(supplier_id);

14. DROP CONSTRAINT trong MySQL

-- Primary key
ALTER TABLE student DROP PRIMARY KEY;

-- Foreign key
ALTER TABLE student
DROP FOREIGN KEY fk_student_department;

-- Check
ALTER TABLE student
DROP CHECK chk_student_gpa;

-- Unique index/constraint
ALTER TABLE student
DROP INDEX uq_student_email;
Cú pháp drop constraint khác nhau giữa DBMS; MySQL đặc biệt dùng DROP FOREIGN KEY cho FK và thường DROP INDEX cho UNIQUE index.

15. RENAME TABLE

ALTER TABLE student RENAME TO students;

RENAME TABLE students TO student;

MySQL còn cho rename nhiều bảng trong cùng statement:

RENAME TABLE
  student TO student_old,
  student_new TO student;

Thực hành 10

Đổi product thành products.

Đáp án
RENAME TABLE product TO products;

16. TRUNCATE TABLE

TRUNCATE TABLE student;

TRUNCATE xóa toàn bộ rows nhưng giữ table structure. Trong MySQL/InnoDB, đây là DDL có implicit commit; không nên giả định có thể rollback như DELETE. Nó cũng có thể bị từ chối nếu table đang được table khác tham chiếu bằng foreign key.

Mất

Tất cả rows.

Giữ

Table structure để dùng tiếp.

Thực hành 11

Làm rỗng staging_import nhưng giữ schema.

Đáp án
TRUNCATE TABLE staging_import;

17. DROP TABLE

DROP TABLE student;

DROP TABLE IF EXISTS student;

DROP TABLE xóa table definition và dữ liệu.

Destructive: nếu cần table lại, phải tạo lại từ schema/backup/migration.

20. DDL và Transaction trong MySQL

Nhiều lệnh DDL như CREATE, ALTER, DROP, RENAME, TRUNCATE gây implicit commit trong MySQL.

START TRANSACTION;

UPDATE student
SET status='INACTIVE'
WHERE student_id=10;

ALTER TABLE student
ADD COLUMN note VARCHAR(200);

ROLLBACK;  -- đừng giả định toàn bộ sẽ trở lại như trước ALTER
Schema migration cần backup, test và kế hoạch triển khai riêng; không xem DDL giống một UPDATE thông thường.

22. Cheat Sheet

CREATE DATABASE IF NOT EXISTS db;
USE db;

CREATE TABLE t (
  id INT PRIMARY KEY,
  name VARCHAR(100) NOT NULL
);

ALTER TABLE t ADD COLUMN email VARCHAR(200);
ALTER TABLE t DROP COLUMN email;
ALTER TABLE t RENAME COLUMN name TO full_name;
ALTER TABLE t MODIFY COLUMN full_name VARCHAR(200) NOT NULL;
ALTER TABLE t CHANGE COLUMN full_name name VARCHAR(200) NOT NULL;

ALTER TABLE t ALTER COLUMN status SET DEFAULT 'ACTIVE';
ALTER TABLE t ALTER COLUMN status DROP DEFAULT;

ALTER TABLE t ADD CONSTRAINT uq_name UNIQUE(name);
ALTER TABLE t ADD CONSTRAINT chk_id CHECK(id > 0);

ALTER TABLE t DROP PRIMARY KEY;
ALTER TABLE t DROP FOREIGN KEY fk_name;
ALTER TABLE t DROP CHECK chk_name;
ALTER TABLE t DROP INDEX uq_name;

ALTER TABLE t RENAME TO t_new;
RENAME TABLE t_new TO t;

TRUNCATE TABLE t;
DROP TABLE IF EXISTS t;

23. Lỗi thường gặp

DROP nhầm TRUNCATE

DROP làm table biến mất.

TRUNCATE có WHERE

Không có.

MODIFY quên NOT NULL

Có thể đổi definition ngoài ý muốn.

Đổi type không kiểm tra data

Conversion có thể fail.

Rename không sửa app

Query dùng tên cũ sẽ hỏng.

DDL rollback như DML

Không đúng trong MySQL.

Nhầm dialect

MySQL MODIFY ≠ PostgreSQL ALTER TYPE.

Không đặt tên constraint

Khó maintain/drop.
