Data Constraints in SQL

Constraints định nghĩa các quy tắc mà dữ liệu phải tuân theo để bảo đảm tính chính xác, nhất quán và ngăn dữ liệu không hợp lệ đi vào database.

1. Tổng quan về Data Constraints

Constraint là quy tắc được DBMS thực thi trên dữ liệu. Khi một INSERT hoặc UPDATE làm vi phạm constraint, DBMS từ chối thao tác thay vì lưu trạng thái không hợp lệ.

Domain integrity

Giá trị phải đúng phạm vi/định dạng mong muốn.

Entity integrity

Mỗi row phải được nhận diện rõ.

Referential integrity

Tham chiếu giữa tables phải hợp lệ.

Business rules

Ví dụ Price ≥ 0, Credits ∈ [1,6].

Quan trọng: constraint nên được đặt trong database ngay cả khi ứng dụng đã kiểm tra dữ liệu. Application validation cải thiện trải nghiệm người dùng; database constraint là lớp bảo vệ cuối cùng cho integrity.

2. Column-level và Table-level Constraints

Column-level

CREATE TABLE student (
    student_id INT PRIMARY KEY,
    full_name  VARCHAR(100) NOT NULL,
    email      VARCHAR(200) UNIQUE,
    gpa        DECIMAL(3,2) CHECK (gpa BETWEEN 0 AND 4)
);

Table-level

CREATE TABLE enrollment (
    student_id INT,
    course_id  INT,
    semester   VARCHAR(20),
    CONSTRAINT pk_enrollment
      PRIMARY KEY (student_id, course_id, semester)
);
Table-level syntax đặc biệt cần thiết cho composite constraints gồm nhiều columns.

3. NOT NULL Constraint

NOT NULL yêu cầu column luôn có giá trị; không chấp nhận NULL. GeeksforGeeks mô tả NOT NULL là constraint dùng cho những attributes bắt buộc phải có dữ liệu.

CREATE TABLE student (
    student_id INT NOT NULL,
    full_name  VARCHAR(100) NOT NULL,
    nickname   VARCHAR(50)          -- có thể NULL
);

NULL không phải 0 hoặc chuỗi rỗng

ValueÝ nghĩa
NULLKhông biết / không có / không áp dụng
0Một giá trị số xác định
''Chuỗi có độ dài 0

Thực hành NOT NULL

Tạo EMPLOYEE sao cho EmployeeID, FullName và HireDate bắt buộc; MiddleName được phép NULL.

Đáp án
CREATE TABLE employee (
  employee_id INT NOT NULL,
  full_name VARCHAR(100) NOT NULL,
  middle_name VARCHAR(100),
  hire_date DATE NOT NULL
);

4. PRIMARY KEY Constraint

PRIMARY KEY nhận diện duy nhất mỗi row. Nó kết hợp hai yêu cầu cốt lõi: unique và NOT NULL. Một table chỉ có một PRIMARY KEY constraint, nhưng key đó có thể gồm nhiều columns.

CREATE TABLE student (
    student_id INT PRIMARY KEY,
    full_name  VARCHAR(100) NOT NULL
);

Named constraint

CREATE TABLE student (
    student_id INT,
    full_name VARCHAR(100),
    CONSTRAINT pk_student PRIMARY KEY (student_id)
);
“Một table chỉ có một primary key” không có nghĩa primary key chỉ có một column. Composite primary key vẫn là một PRIMARY KEY constraint.

Thực hành PRIMARY KEY

Tạo DEPARTMENT(DepartmentID, DepartmentName), trong đó DepartmentID là PK.

Đáp án
CREATE TABLE department (
  department_id INT PRIMARY KEY,
  department_name VARCHAR(100) NOT NULL
);

5. FOREIGN KEY Constraint

FOREIGN KEY bảo vệ referential integrity: giá trị FK phải tham chiếu tới một row hợp lệ ở table được tham chiếu, hoặc có thể NULL nếu column cho phép NULL.

CREATE TABLE department (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100) NOT NULL
);

CREATE TABLE employee (
    employee_id INT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    department_id INT NOT NULL,
    CONSTRAINT fk_employee_department
      FOREIGN KEY (department_id)
      REFERENCES department(department_id)
);

Quan hệ 1:N

DEPARTMENT 1 ───── N EMPLOYEE

Nhiều employees có thể có cùng DepartmentID, vì vậy foreign key không mặc định unique.

Referential actions

FOREIGN KEY (department_id)
REFERENCES department(department_id)
ON UPDATE CASCADE
ON DELETE RESTRICT
ActionÝ nghĩa khái quát
RESTRICT / NO ACTIONNgăn thao tác làm mất reference hợp lệ.
CASCADELan truyền update/delete sang child rows.
SET NULLĐặt FK thành NULL nếu column cho phép.
CASCADE không phải lúc nào cũng tốt. Phải chọn theo business semantics, không dùng chỉ để “xóa cho tiện”.

Thực hành FOREIGN KEY

Tạo COURSE và SECTION sao cho mỗi SECTION bắt buộc thuộc đúng một COURSE.

Đáp án
CREATE TABLE course (
  course_id INT PRIMARY KEY,
  course_name VARCHAR(150) NOT NULL
);

CREATE TABLE section (
  section_id INT PRIMARY KEY,
  course_id INT NOT NULL,
  CONSTRAINT fk_section_course
    FOREIGN KEY (course_id)
    REFERENCES course(course_id)
);

6. COMPOSITE KEY

Composite key là key gồm ít nhất hai columns. Đây là một khái niệm về cấu trúc của key, không phải một từ khóa constraint độc lập trong SQL.

ENROLLMENT(StudentID, CourseID, Semester, Grade)
CREATE TABLE enrollment (
    student_id INT,
    course_id  INT,
    semester   VARCHAR(20),
    grade      DECIMAL(4,2),

    CONSTRAINT pk_enrollment
      PRIMARY KEY (student_id, course_id, semester)
);

Từng column riêng lẻ có thể lặp; tổ hợp của chúng phải unique.

StudentID

Lặp vì SV học nhiều course.

CourseID

Lặp vì course có nhiều SV.

Tổ hợp

StudentID + CourseID + Semester nhận diện enrollment.

Thực hành COMPOSITE KEY

ROOM có RoomNumber chỉ unique trong HOTEL. Tạo HOTEL_ROOM với composite PK.

Đáp án
CREATE TABLE hotel_room (
  hotel_id INT,
  room_number INT,
  room_type VARCHAR(30),
  price DECIMAL(12,2),
  PRIMARY KEY (hotel_id, room_number)
);

7. UNIQUE Constraint

UNIQUE ngăn duplicate trên một column hoặc tập columns. Một table có thể có nhiều UNIQUE constraints.

CREATE TABLE user_account (
    user_id  BIGINT PRIMARY KEY,
    username VARCHAR(50)  UNIQUE NOT NULL,
    email    VARCHAR(200) UNIQUE NOT NULL
);

Composite UNIQUE

CREATE TABLE room_booking (
    booking_id INT PRIMARY KEY,
    room_id INT NOT NULL,
    booking_date DATE NOT NULL,
    CONSTRAINT uq_room_date
      UNIQUE (room_id, booking_date)
);

PRIMARY KEY vs UNIQUE

Tiêu chíPRIMARY KEYUNIQUE
Vai tròIdentifier chínhBảo vệ business uniqueness
Số constraintMột PK/tableCó thể nhiều
NULLKhông cho phépHành vi NULL phụ thuộc DBMS
Có thể composite?CóCó
Không nên học thuộc “UNIQUE luôn cho phép nhiều NULL” như luật SQL chung. Hành vi NULL trong unique constraint/index có khác biệt giữa các DBMS. Trong MySQL, unique index có thể chứa nhiều NULL values.

Thực hành UNIQUE

PRODUCT dùng ProductID làm PK, nhưng SKU và Barcode cũng phải duy nhất. Viết CREATE TABLE.

Đáp án
CREATE TABLE product (
  product_id INT PRIMARY KEY,
  sku VARCHAR(50) UNIQUE NOT NULL,
  barcode VARCHAR(50) UNIQUE NOT NULL,
  product_name VARCHAR(150) NOT NULL
);

8. ALTERNATE KEY

Alternate key là một candidate key không được chọn làm primary key. Đây là khái niệm thiết kế quan hệ, không phải từ khóa SQL riêng.

Candidate Keys = {StudentID}, {CitizenID}, {Email}
Primary Key = {StudentID}
Alternate Keys = {CitizenID}, {Email}

Hiện thực trong SQL

CREATE TABLE student (
    student_id INT PRIMARY KEY,
    citizen_id VARCHAR(20) UNIQUE NOT NULL,
    email      VARCHAR(200) UNIQUE NOT NULL,
    full_name  VARCHAR(100) NOT NULL
);
UNIQUE + NOT NULL thường là cách rõ ràng để giữ semantics của alternate candidate key trong SQL.

Thực hành ALTERNATE KEY

VEHICLE có VehicleID, VIN và RegistrationNo đều unique. Chọn VehicleID làm PK. Hai alternate keys còn lại được biểu diễn thế nào?

Đáp án
CREATE TABLE vehicle (
  vehicle_id INT PRIMARY KEY,
  vin VARCHAR(50) UNIQUE NOT NULL,
  registration_no VARCHAR(30) UNIQUE NOT NULL
);

9. CHECK Constraint

CHECK bắt buộc dữ liệu phải thỏa một predicate. Nếu điều kiện được đánh giá là FALSE, INSERT/UPDATE bị từ chối.

CREATE TABLE product (
    product_id INT PRIMARY KEY,
    product_name VARCHAR(150) NOT NULL,
    price DECIMAL(12,2) CHECK (price >= 0),
    stock INT CHECK (stock >= 0)
);

CHECK nhiều columns

CREATE TABLE promotion (
    promotion_id INT PRIMARY KEY,
    start_date DATE NOT NULL,
    end_date   DATE NOT NULL,
    CONSTRAINT chk_promotion_dates
      CHECK (end_date >= start_date)
);

CHECK và NULL

Nếu column được phép NULL, một biểu thức CHECK có thể không ngăn NULL vì SQL sử dụng three-valued logic. Nếu muốn vừa có điều kiện vừa bắt buộc giá trị, kết hợp NOT NULL.

age INT NOT NULL CHECK (age >= 18)

Thực hành CHECK

Tạo COURSE sao cho Credits từ 1–6 và TuitionFee không âm.

Đáp án
CREATE TABLE course (
  course_id INT PRIMARY KEY,
  credits INT NOT NULL CHECK (credits BETWEEN 1 AND 6),
  tuition_fee DECIMAL(12,2) NOT NULL CHECK (tuition_fee >= 0)
);

10. DEFAULT Constraint

DEFAULT cung cấp giá trị mặc định khi INSERT không chỉ định giá trị cho column đó.

CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    status VARCHAR(20) NOT NULL DEFAULT 'NEW',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

DEFAULT không thay cho NOT NULL

DEFAULT xử lý trường hợp không cung cấp column. Nếu column cho phép NULL và người dùng chủ động insert NULL, semantics có thể khác tùy DBMS/mode.

DEFAULT = “nếu không cung cấp thì dùng gì?”
NOT NULL = “có được phép thiếu giá trị không?”

Thực hành DEFAULT

Tạo TASK với Status mặc định 'TODO', Priority mặc định 3, CreatedAt mặc định thời điểm hiện tại.

Đáp án
CREATE TABLE task (
  task_id INT PRIMARY KEY,
  task_name VARCHAR(150) NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'TODO',
  priority INT NOT NULL DEFAULT 3,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

11. Kết hợp nhiều Constraints

Trong thiết kế thực tế, một column thường đồng thời chịu nhiều constraints.

CREATE TABLE employee (
    employee_id INT PRIMARY KEY,

    employee_code VARCHAR(20)
        UNIQUE
        NOT NULL,

    full_name VARCHAR(100)
        NOT NULL,

    salary DECIMAL(12,2)
        NOT NULL
        CHECK (salary >= 0),

    status VARCHAR(20)
        NOT NULL
        DEFAULT 'ACTIVE',

    department_id INT
        NOT NULL,

    CONSTRAINT fk_employee_department
      FOREIGN KEY (department_id)
      REFERENCES department(department_id)
);
Constraint design nên xuất phát từ business rules. Không thêm constraint vì “thường người ta làm vậy”; mỗi constraint cần trả lời một quy tắc dữ liệu cụ thể.

12. Thêm và xóa Constraints sau khi tạo Table

ADD UNIQUE

ALTER TABLE student
ADD CONSTRAINT uq_student_email
UNIQUE (email);

ADD CHECK

ALTER TABLE student
ADD CONSTRAINT chk_student_gpa
CHECK (gpa BETWEEN 0 AND 4);

ADD FOREIGN KEY

ALTER TABLE student
ADD CONSTRAINT fk_student_department
FOREIGN KEY (department_id)
REFERENCES department(department_id);

MySQL: drop constraints

ALTER TABLE student DROP PRIMARY KEY;

ALTER TABLE student
DROP FOREIGN KEY fk_student_department;

ALTER TABLE student
DROP CHECK chk_student_gpa;

ALTER TABLE student
DROP INDEX uq_student_email;
Cú pháp DROP constraint là vùng khác biệt đáng kể giữa MySQL, PostgreSQL và SQL Server. Bài này dùng MySQL làm dialect chính.

14. Điều gì xảy ra khi dữ liệu vi phạm Constraint?

Duplicate PRIMARY KEY

INSERT INTO student(student_id, full_name)
VALUES (1, 'An');

INSERT INTO student(student_id, full_name)
VALUES (1, 'Binh');
-- ERROR: duplicate primary key

Foreign key không tồn tại

INSERT INTO employee(employee_id, full_name, department_id)
VALUES (10, 'An', 999);
-- ERROR nếu DepartmentID=999 không tồn tại

CHECK thất bại

INSERT INTO product(product_id, product_name, price)
VALUES (1, 'Laptop', -100);
-- ERROR: CHECK constraint violated

NOT NULL thất bại

INSERT INTO employee(employee_id, full_name)
VALUES (11, NULL);
-- ERROR nếu full_name NOT NULL
Cách dạy hiệu quả: sau mỗi constraint, yêu cầu sinh viên viết một INSERT hợp lệ và một INSERT cố tình vi phạm, rồi đọc error message.

15. Thiết kế Constraints từ Business Rules

Business RuleConstraint phù hợp
Mỗi sinh viên phải có tênFullName NOT NULL
Mã sinh viên không được trùngPRIMARY KEY hoặc UNIQUE NOT NULL
Email đăng nhập không được trùngUNIQUE NOT NULL
Mỗi employee thuộc một department tồn tạiFK + NOT NULL
Price không âmCHECK (Price >= 0)
Status mặc định NEWDEFAULT 'NEW'
Mỗi room number unique trong hotelComposite PRIMARY KEY(HotelID, RoomNumber)
VIN là candidate key nhưng VehicleID được chọn làm PKVIN UNIQUE NOT NULL → alternate key

Thực hành thiết kế

Chuyển các business rules sau thành constraints:

  1. Username bắt buộc và không trùng.
  2. Age phải từ 18 đến 65.
  3. Mỗi order bắt buộc thuộc một customer tồn tại.
  4. Order status mặc định là PENDING.
Gợi ý
username VARCHAR(50) NOT NULL UNIQUE,
age INT NOT NULL CHECK (age BETWEEN 18 AND 65),
customer_id INT NOT NULL,
status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
FOREIGN KEY (customer_id) REFERENCES customer(customer_id)

16. Lab tổng hợp: University Registration

Xây dựng ba tables DEPARTMENT, STUDENT và ENROLLMENT, sử dụng tất cả constraint chính.

CREATE TABLE department (
    department_id INT PRIMARY KEY,
    department_code VARCHAR(20) NOT NULL UNIQUE,
    department_name VARCHAR(100) NOT NULL
);

CREATE TABLE student (
    student_id INT PRIMARY KEY,
    student_code VARCHAR(20) NOT NULL UNIQUE,
    email VARCHAR(200) NOT NULL UNIQUE,
    full_name VARCHAR(100) NOT NULL,
    gpa DECIMAL(3,2),
    status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
    department_id INT NOT NULL,

    CONSTRAINT chk_student_gpa
      CHECK (gpa IS NULL OR gpa BETWEEN 0 AND 4),

    CONSTRAINT fk_student_department
      FOREIGN KEY (department_id)
      REFERENCES department(department_id)
);

CREATE TABLE enrollment (
    student_id INT,
    course_id INT,
    semester VARCHAR(20),
    grade DECIMAL(4,2),

    CONSTRAINT pk_enrollment
      PRIMARY KEY (student_id, course_id, semester),

    CONSTRAINT fk_enrollment_student
      FOREIGN KEY (student_id)
      REFERENCES student(student_id),

    CONSTRAINT chk_enrollment_grade
      CHECK (grade IS NULL OR grade BETWEEN 0 AND 10)
);

Nhiệm vụ thực hành

  1. INSERT một department hợp lệ.
  2. INSERT một student hợp lệ.
  3. Thử student trùng Email.
  4. Thử student có GPA=5.
  5. Thử student tham chiếu DepartmentID không tồn tại.
  6. Thử hai enrollment trùng composite PK.
  7. Quan sát lỗi của DBMS và giải thích constraint nào đã ngăn thao tác.

17. Bài tập củng cố

Bài 1 — E-commerce

Thiết kế CUSTOMER, PRODUCT, ORDERS với các quy tắc: email customer unique; price ≥ 0; stock ≥ 0; order phải thuộc customer; order status mặc định NEW.

Bài 2 — Hotel

HOTEL_ROOM có RoomNumber chỉ unique trong HotelID. Price > 0. Status mặc định AVAILABLE. Viết CREATE TABLE đầy đủ.

Bài 3 — Employee

EmployeeCode và WorkEmail đều candidate keys; chọn EmployeeID làm PK. Viết constraints để hai key còn lại trở thành alternate keys.

Bài 4 — CHECK nhiều cột

PROJECT(StartDate, EndDate, Budget). EndDate không được trước StartDate và Budget ≥ 0.

Bài 5 — Debug

Tại sao schema sau chưa thực sự bảo đảm Email là candidate key?

CREATE TABLE user_account (
  user_id INT PRIMARY KEY,
  email VARCHAR(200) UNIQUE
);
Gợi ý

Nếu semantics yêu cầu Email luôn tồn tại và unique, cần thêm NOT NULL. UNIQUE một mình không biểu đạt đầy đủ yêu cầu “candidate key bắt buộc có giá trị”.

Bài 6 — Phân biệt khái niệm

Giải thích vì sao COMPOSITE KEY và ALTERNATE KEY không nên được mô tả như hai constraint keywords ngang hàng với PRIMARY KEY, FOREIGN KEY hay CHECK.
