Chặng 1

MySQL trong Hệ sinh thái RDBMS & Đặc tính Cốt lõi

Khái niệm RDBMS, mô hình Client-Server và tính tuân thủ ACID

1. MySQL là gì?

MySQL là một Hệ quản trị cơ sở dữ liệu quan hệ mã nguồn mở (Open-source Relational Database Management System - RDBMS) được bảo trợ và phát triển bởi Tập đoàn Oracle. MySQL tổ chức dữ liệu thành các bảng gồm dòng (rows) và cột (columns), sử dụng chuẩn SQL (Structured Query Language) để thao tác dữ liệu.

2. Các đặc tính cốt lõi của MySQL:

  • Mô hình Client-Server: Máy chủ MySQL (tiến trình mysqld) chạy nền tập trung, phục vụ đồng thời hàng nghìn kết nối từ các client khác nhau (ứng dụng web, script, GUI tool).
  • Đa luồng (Multi-threaded): Được thiết kế theo cơ chế đa luồng giúp tận dụng tối đa sức mạnh của CPU đa lõi để xử lý các truy vấn đồng thời.
  • Tuân thủ ACID: Khi sử dụng storage engine mặc định (InnoDB), MySQL đảm bảo đầy đủ 4 tính chất: Atomicity (Nguyên tử), Consistency (Nhất quán), Isolation (Cô lập), Durability (Bền vững).
  • Hệ thống xác thực mạnh mẽ: Hỗ trợ mã hóa kết nối qua SSL/TLS và thuật toán băm mật khẩu hiện đại caching_sha2_password.

Chặng 2

Kiến trúc Đa tầng của MySQL Server

Phân tích 3 tầng: Connection Layer, SQL Layer và Storage Engine Layer

Sơ đồ Kiến trúc Đa tầng trong MySQL Server:

+-------------------------------------------------------------+
| Tầng 1: Connection & Thread Handling (Quản lý Kết nối)      |
| -> Xác thực (Authentication), Kiểm tra quyền, Thread Pool   |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| Tầng 2: SQL Layer (Bộ máy Xử lý SQL)                        |
| -> Parser & Preprocessor: Phân tích cú pháp & kiểm tra bảng |
| -> Optimizer: Bộ tối ưu hóa chọn Execution Plan tốt nhất    |
| -> Query Execution Engine: Bộ máy thực thi lệnh             |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| Tầng 3: Pluggable Storage Engine API                        |
| -> Giao tiếp thống nhất với InnoDB, MyISAM, Memory, CSV...  |
+-------------------------------------------------------------+
                              |
                              v
             File System / Data Directory (Đĩa cứng)

Nhiệm vụ của từng tầng:

  • Tầng 1 (Connection Layer): Quản lý kết nối từ client (TCP/IP port 3306 hoặc local Unix Socket/Named Pipe). Cấp phát một luồng (thread) xử lý riêng cho mỗi client và xác thực username/password.
  • Tầng 2 (SQL Layer):
    • Parser (Bộ phân tích cú pháp): Tạo cây cú pháp (Parse Tree) và kiểm tra lỗi chính tả SQL.
    • Preprocessor: Kiểm tra sự tồn tại của database, table, cột và quyền người dùng.
    • Optimizer (Bộ tối ưu hóa): Tính toán chi phí thực thi (cost-based optimizer), quyết định thứ tự JOIN và chọn Index tối ưu nhất.
  • Tầng 3 (Storage Engine Layer): Chịu trách nhiệm lưu trữ và truy xuất các dòng dữ liệu thực tế từ đĩa cứng hoặc RAM.

Chặng 3

Tiến trình máy chủ `mysqld` & Vòng đời Xử lý Query

Quy trình từ lúc Client gửi gói tin đến khi nhận Result Set

Vòng đời hoàn chỉnh của một truy vấn SQL:

  1. Client gửi truy vấn: Ứng dụng gửi câu lệnh SQL qua giao thức mạng MySQL Protocol (mặc định port 3306).
  2. Kiểm tra kết nối & quyền: Luồng phục vụ (thread) của connection đó tiếp nhận gói tin và xác thực quyền SELECT/UPDATE trên đối tượng.
  3. Phân tích & Tối ưu: Bộ Parser tạo cây cú pháp, Optimizer xây dựng kế hoạch thực thi (Execution Plan).
  4. Gọi Storage Engine: Execution engine gọi các hàm trừu tượng trong Storage Engine API (ví dụ: rnd_next(), index_read()).
  5. Truy xuất dữ liệu đĩa/RAM: Storage Engine (ví dụ InnoDB) đọc trang dữ liệu (Data Pages) từ Buffer Pool trong RAM; nếu chưa có trong RAM, nạp từ đĩa cứng xuống.
  6. Trả kết quả: Server gửi tập kết quả (Result Set) về client từng khối qua giao thức mạng.

Phân biệt `mysqld`, `mysql` CLI, và MySQL Workbench

Hiểu rõ ranh giới giữa Service Daemon, Công cụ Dòng lệnh và Giao diện Đồ họa
Thành phần Bản chất Vai trò chính Môi trường điển hình
mysqld Daemon Process Lắng nghe port 3306, thực thi query, bảo vệ file dữ liệu, lưu trữ đĩa Chạy ngầm (Windows Service hoặc Linux systemd)

MySQL Workbench GUI Application Môi trường đồ họa: thiết kế mô hình EER, viết SQL, giám sát hiệu năng Máy tính của lập trình viên / Quản trị viên (DBA)

Ghi nhớ quan trọng: Client (dù là Workbench hay CLI hay ứng dụng Spring Boot / Node.js) không trực tiếp chạm vào các file dữ liệu trên ổ đĩa, mà luôn phải giao tiếp qua tiến trình mysqld.

Chặng 5

Giao diện Pluggable Storage Engine & Tính Độc lập Dữ liệu

Kiến trúc cắm rút Storage Engine độc đáo và lợi ích vận hành

1. Kiến trúc Pluggable Storage Engine

Điểm làm nên sự khác biệt của MySQL so với các hệ CSDL khác (như PostgreSQL, Oracle Database) là kiến trúc lưu trữ dạng mô-đun cắm rút (Pluggable Storage Engine Architecture). Tầng SQL Layer hoàn toàn tách biệt với tầng lưu trữ vật lý.

2. Giao diện Handler API:

  • Tầng trên của MySQL giao tiếp với các engine thông qua một tập các hàm giao diện tiêu chuẩn gọi là Handler API.
  • Tất cả các engine (InnoDB, MyISAM, Memory, CSV...) đều phải hiện thực hóa (implement) các thao tác chuẩn như: mở bảng, đọc dòng kế tiếp, tìm theo chỉ mục, chèn dòng mới, cập nhật dòng, xóa dòng.
  • Lợi ích: Người dùng có thể chọn các engine khác nhau cho từng bảng cụ thể trong cùng một cơ sở dữ liệu tùy thuộc vào đặc thù truy vấn (ví dụ: dùng MEMORY cho bảng session tra cứu cực nhanh, dùng InnoDB cho bảng giao dịch mua hàng).
