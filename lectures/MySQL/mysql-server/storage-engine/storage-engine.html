Khái niệm Pluggable Storage Engine trong MySQL

Kiến trúc cắm rút độc đáo và tính độc lập dữ liệu vật lý

1. Storage Engine là gì?

Storage Engine (động cơ lưu trữ) là thành phần phần mềm trực tiếp chịu trách nhiệm thực hiện các thao tác: tạo bảng, đọc, ghi, khóa (locking), lập chỉ mục (indexing) và khôi phục dữ liệu vật lý trên thiết bị lưu trữ.

2. Sự khác biệt ở cấp độ bảng (Per-table Engine):

Trong MySQL, bạn có thể chỉ định Storage Engine cho từng bảng độc lập khi tạo bảng bằng mệnh đề ENGINE = ...:

CREATE TABLE user_sessions (
    session_id VARCHAR(64) PRIMARY KEY,
    user_id INT,
    last_active TIMESTAMP
) ENGINE = MEMORY; -- Lưu bảng này trong RAM để truy cập siêu tốc

Nếu không chỉ định rõ, MySQL sẽ tự động gán engine mặc định được quy định bởi biến default_storage_engine (mặc định là InnoDB).

InnoDB Engine — Tiêu chuẩn Doanh nghiệp

Giao dịch ACID, Khóa cấp dòng (Row-level locking) và Toàn vẹn Khóa ngoại

5 Tính năng then chốt biến InnoDB thành Engine mặc định của MySQL:

  • Hỗ trợ Giao dịch ACID trọn vẹn: Hỗ trợ các lệnh COMMIT, ROLLBACK và SAVEPOINT.
  • Khóa cấp dòng (Row-level Locking): Khi cập nhật một dòng, chỉ có đúng dòng đó bị khóa; các tiến trình khác vẫn có thể đọc/ghi các dòng khác trong cùng một bảng bình thường, mang lại hiệu năng đồng thời (concurrency) cực cao.
  • Ràng buộc Khóa ngoại (Foreign Key Constraints): Tự động kiểm tra tính toàn vẹn tham chiếu giữa các bảng với các cơ chế CASCADE, RESTRICT, SET NULL.
  • Kiểm soát Đồng thời Đa phiên bản (MVCC): Cho phép các câu lệnh SELECT đọc dữ liệu nhất quán mà không bị chặn bởi các lệnh UPDATE/INSERT (Non-blocking reads).
  • Phục hồi khi gặp sự cố (Crash Recovery): Tự động sử dụng Redo Log và Undo Log để tái lập tính nhất quán của dữ liệu ngay khi khởi động lại sau crash.

Cấu trúc CSDL Mẫu Doanh nghiệp `classicmodels`

Khám phá mô hình quan hệ bán hàng 8 bảng kinh điển của MySQL

Mô hình quan hệ 8 bảng trong CSDL `classicmodels`:

classicmodels là cơ sở dữ liệu mẫu chuẩn của MySQL mô phỏng hoạt động kinh doanh bán xe và mô hình cổ điển của một công ty thương mại:

  • offices (Văn phòng đại diện): Lưu các chi nhánh toàn cầu. officeCode là khóa chính.
  • employees (Nhân viên): Quan hệ nhiều-1 với offices. Có mối quan hệ tự tham chiếu (Self-referencing Foreign Key): cột reportsTo trỏ về chính employeeNumber của người quản lý.
  • customers (Khách hàng): Mỗi khách hàng được gán cho một nhân viên bán hàng qua salesRepEmployeeNumber.
  • orders (Đơn đặt hàng): Quan hệ 1-nhiều với customers (một khách có nhiều đơn).
  • orderdetails (Chi tiết đơn hàng): Bảng cầu nối liên kết đơn hàng với sản phẩm. Khóa chính ghép: (orderNumber, productCode).
  • products & productlines: Danh mục sản phẩm và dòng sản phẩm phân loại (Classic Cars, Motorcycles, Planes...).
  • payments (Thanh toán): Lưu lịch sử thanh toán của khách hàng. Khóa chính ghép: (customerNumber, checkNumber).

Quy trình Nạp & Kiểm tra Dữ liệu Mẫu (`SOURCE`)

Import script `classicmodels.sql` và kiểm tra toàn vẹn dữ liệu

1. Các bước nạp dữ liệu mẫu bằng dòng lệnh MySQL CLI:

# Bước 1: Mở Command Prompt hoặc Terminal, kết nối vào MySQL
mysql -u root -p

# Bước 2: Thực thi script nạp dữ liệu bằng lệnh SOURCE (dùng dấu chéo xuôi '/')
SOURCE E:/MinhVD/Github/DBMS/lectures/MySQL/mysql-server/mysql-sample-database/classicmodels.sql;

# Bước 3: Kiểm tra database đã được tạo thành công
SHOW DATABASES LIKE 'classicmodels';
USE classicmodels;
SHOW TABLES;

2. Xác minh số lượng dòng dữ liệu:

-- Kiểm tra số lượng khách hàng (chuẩn là 122 dòng)
SELECT COUNT(*) FROM customers;

-- Kiểm tra số lượng đơn hàng (chuẩn là 326 dòng)
SELECT COUNT(*) FROM orders;
