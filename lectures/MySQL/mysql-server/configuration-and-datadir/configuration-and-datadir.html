Cấu hình Hệ thống & Thư mục Dữ liệu MySQL

Khám phá cấu trúc file cấu hình my.ini/my.cnf, phân biệt biến hệ thống động/tĩnh, quản trị thư mục dữ liệu datadir và hệ thống log (Redo, Undo, Binlog).

Chặng: 1/5 Điểm: 0/100
Chặng 1

Option Files & Thứ tự Ưu tiên (Precedence)

Quy tắc nạp file `my.ini` / `my.cnf` và thứ tự ghi đè tham số cấu hình

1. Vị trí file cấu hình phổ biến:

  • Windows: Thường nằm tại C:\ProgramData\MySQL\MySQL Server 8.0\my.ini (thư mục ProgramData bị ẩn mặc định trong File Explorer).
  • Linux: Thường nằm tại /etc/mysql/my.cnf hoặc /etc/my.cnf.

2. Quy tắc thứ tự ưu tiên (Precedence):

Khi khởi động, `mysqld` tìm kiếm option files theo danh sách đường dẫn cố định. Nếu cùng một tham số cấu hình xuất hiện ở nhiều file khác nhau, file đọc sau sẽ ghi đè giá trị của file đọc trước. Ngoài ra, tham số truyền trực tiếp qua dòng lệnh (Command Line Arguments khi gõ mysqld --port=3307) có mức ưu tiên cao nhất, ghi đè toàn bộ file cấu hình.

Câu 1: Trong hệ thống phân cấp cấu hình của MySQL, nguồn thiết lập tham số nào có mức ưu tiên cao nhất (ghi đè mọi thiết lập khác)?
Câu 2: Trên Windows, thư mục hệ thống mặc định chứa file cấu hình `my.ini` của MySQL Server 8.0 là thư mục nào?
Chặng 2

Cấu trúc Option Groups: `[mysqld]`, `[client]`, `[mysql]`

Phân định phạm vi ảnh hưởng của từng khối tùy chọn trong file cấu hình

Ví dụ cấu trúc các Option Groups chuẩn:

# Nhóm chỉ áp dụng cho tiến trình máy chủ mysqld
[mysqld]
port=3306
datadir="C:/ProgramData/MySQL/MySQL Server 8.0/Data"
default_storage_engine=InnoDB
max_connections=200
innodb_buffer_pool_size=256M

# Nhóm áp dụng chung cho mọi client kết nối (mysql, workbench, python...)
[client]
port=3306
default-character-set=utf8mb4

# Nhóm cấu hình riêng cho ứng dụng terminal mysql CLI
[mysql]
no-auto-rehash

Nguyên tắc quan trọng: Nếu đặt một tham số máy chủ như innodb_buffer_pool_size vào nhóm [client], các chương trình client khi khởi động sẽ báo lỗi cú pháp vì client không nhận diện được các tùy chọn của server daemon.

🎯 Checkpoint Chặng 2
Câu 1: Trong file cấu hình MySQL, để thay đổi kích thước bộ đệm `innodb_buffer_pool_size` của máy chủ, tham số này BẮT BUỘC phải nằm trong Option Group nào?
Câu 2: Mục đích của Option Group `[client]` trong file cấu hình là gì?
Chặng 3

Biến Hệ thống (System Variables): Global vs Session & Dynamic vs Static

Tra cứu bằng `SHOW VARIABLES` và cấu hình tức thời bằng `SET GLOBAL`

1. Phân loại theo phạm vi (Scope):

  • GLOBAL: Tác động đến hành vi của toàn bộ MySQL Server và áp dụng cho tất cả client kết nối sau thời điểm thay đổi. 
    SHOW GLOBAL VARIABLES LIKE 'max_connections';
  • SESSION: Chỉ có hiệu lực riêng cho kết nối hiện tại của phiên làm việc đó. Khi đóng phiên, thay đổi mất đi. 
    SHOW SESSION VARIABLES LIKE 'sql_mode';

2. Phân loại theo tính linh hoạt lúc runtime:

  • Dynamic Variables (Biến động): Có thể thay đổi tức thì mà không cần restart server: 
    SET GLOBAL max_connections = 300;
  • Static Variables (Biến tĩnh): Chỉ đọc lúc khởi động server (như datadir, port). Không thể thay đổi bằng SET GLOBAL; bắt buộc phải sửa file cấu hình và restart service.
🎯 Checkpoint Chặng 3
Câu 1: Câu lệnh SQL nào sau đây thay đổi giới hạn số kết nối đồng thời tối đa lên 250 có hiệu lực tức thời cho toàn server mà không cần restart?
Câu 2: Tham số hệ thống nào sau đây là một Biến tĩnh (Static Variable) KHÔNG THỂ thay đổi bằng lệnh `SET GLOBAL` lúc runtime?
Chặng 4

Thư mục Dữ liệu `datadir` & Cấu trúc File Lưu trữ

Khám phá Tablespace `.ibd`, System Tablespace `ibdata1` và các schema thư mục

1. Cách xác định thư mục dữ liệu an toàn bằng SQL:

SHOW VARIABLES LIKE 'datadir';

2. Tổ chức bên trong `datadir`:

  • Thư mục Schema: Mỗi database (như classicmodels) có một thư mục con tương ứng mang tên database đó.
  • File Tablespace (*.ibd): Trong chế độ mặc định innodb_file_per_table=ON, mỗi bảng có file ten_bang.ibd riêng chứa toàn bộ dữ liệu dòng và cây B-Tree chỉ mục của bảng.
  • System Tablespace (ibdata1): File lưu trữ dùng chung của InnoDB (chứa doublewrite buffer, change buffer).
  • Cảnh báo nghiêm ngặt: Tuyệt đối không can thiệp, đổi tên hay xóa các file trong datadir bằng File Explorer khi mysqld đang chạy vì sẽ dẫn đến hỏng cấu trúc Tablespace và không thể khôi phục CSDL.
🎯 Checkpoint Chặng 4
Câu 1: Trong MySQL 8.0 với thiết lập `innodb_file_per_table = ON`, dữ liệu các dòng và cây chỉ mục B-Tree của bảng `customers` được lưu trong file có phần mở rộng nào?
Câu 2: Vì sao người quản trị KHÔNG ĐƯỢC tự ý copy/xóa thủ công file `.ibd` trong thư mục `datadir` khi máy chủ MySQL đang chạy?
Chặng 5

Hệ thống Log Dữ liệu: Redo Log, Undo Log & Binary Log

Nguyên lý Write-Ahead Logging (WAL), bảo đảm tính Durability và phục hồi PITR
Loại Log Cấp độ Mục đích cốt lõi Hành vi khi có sự cố
Redo Log (#ib_redo*) Storage Engine (InnoDB) Bảo đảm tính Durability (Độ bền) trong ACID theo nguyên lý Write-Ahead Logging (WAL). Khi server mất điện đột ngột, InnoDB đọc Redo Log để chạy lại (redo) các giao dịch đã COMMIT nhưng chưa kịp ghi ra đĩa.
Undo Log Storage Engine (InnoDB) Lưu trạng thái dữ liệu trước khi sửa đổi, phục vụ lệnh ROLLBACK và cơ chế đọc cô lập MVCC. Nếu một transaction bị lỗi hoặc người dùng ROLLBACK, Undo log khôi phục các dòng về trạng thái ban đầu.
Binary Log (Binlog) MySQL Server (SQL Layer) Ghi lại tuần tự mọi sự kiện thay đổi dữ liệu để phục vụ Nhân bản (Replication) và Khôi phục về điểm thời gian (PITR). Dùng để đồng bộ dữ liệu sang Server Replica hoặc phục hồi CSDL về đúng thời điểm trước khi có lỗi con người.
🎯 Checkpoint Chặng 5
Câu 1: File log nào của InnoDB chịu trách nhiệm thực thi nguyên tắc "Write-Ahead Logging" để đảm bảo các transaction đã COMMIT không bị mất khi mất điện đột ngột?
Câu 2: Loại log nào hoạt động ở tầng máy chủ (SQL Layer) để phục vụ sao chép dữ liệu giữa các máy chủ (Replication) và khôi phục CSDL về một thời điểm cụ thể trong quá khứ?
