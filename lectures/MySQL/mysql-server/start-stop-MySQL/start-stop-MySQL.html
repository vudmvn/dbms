Vòng đời Server & Quản lý Dịch vụ MySQL

Nắm vững phương thức Start, Stop, Restart dịch vụ MySQL trên Windows và Linux; nguyên lý Graceful Shutdown bảo vệ dữ liệu và cách đọc Error Log chẩn đoán sự cố.

Trạng thái Hoạt động của MySQL & Tác động của Restart

Khi nào cần Restart, khi nào KHÔNG nên Restart và rủi ro gián đoạn dịch vụ

1. Tác động của hành động Restart trên môi trường thực tế:

  • Ngắt kết nối ứng dụng (Connection Drops): Tất cả client đang kết nối sẽ bị ngắt đột ngột.
  • Hủy bỏ các Transaction chưa commit: Các giao dịch đang dở dang sẽ bị Rollback khi server khởi động lại.
  • Mất bộ đệm RAM (Buffer Pool Cold-start): Vùng nhớ đệm InnoDB Buffer Pool bị giải phóng, khiến các truy vấn ngay sau restart chạy chậm hơn đáng kể do phải đọc trực tiếp từ đĩa cứng.

Quản lý MySQL Service trên Windows

Sử dụng `services.msc`, `net start/stop`, `sc.exe` và PowerShell `Start-Service`

Các phương thức điều khiển MySQL Service trên Windows:

  • Giao diện đồ họa Services (GUI):

    Nhấn Win + R, gõ services.msc. Tìm service có tên MySQL80 (hoặc tên đặt lúc cài đặt), chuột phải chọn Start, Stop hoặc Restart.

  • Command Prompt (CMD - Yêu cầu Run as Administrator): 
    REM Khởi động dịch vụ
net start MySQL80

REM Dừng dịch vụ an toàn
net stop MySQL80
  • PowerShell (Administrator): 
    # Kiểm tra trạng thái
Get-Service MySQL80

# Khởi động / Dừng / Khởi động lại
Start-Service MySQL80
Stop-Service MySQL80
Restart-Service MySQL80

Quản lý MySQL Service trên Linux

Sử dụng `systemctl`, `service` và công cụ theo dõi nhật ký `journalctl`

Các lệnh quản trị dịch vụ với systemd trên Ubuntu/Debian/CentOS:

# 1. Kiểm tra trạng thái dịch vụ (Active: active (running))
sudo systemctl status mysql

# 2. Khởi động dịch vụ
sudo systemctl start mysql

# 3. Dừng dịch vụ an toàn
sudo systemctl stop mysql

# 4. Khởi động lại dịch vụ
sudo systemctl restart mysql

# 5. Bật tự động khởi chạy khi boot máy chủ
sudo systemctl enable mysql

# 6. Xem log hệ thống của MySQL qua journalctl
sudo journalctl -u mysql -n 50 --no-pager

Graceful Shutdown vs Forced Kill & Cơ chế `mysqladmin`

Nguyên lý dừng có kiểm soát để bảo vệ cấu trúc Tablespace và Redo Log

1. Quá trình Graceful Shutdown diễn ra như thế nào?

Khi dừng an toàn (bằng systemctl stop, net stop hoặc mysqladmin shutdown):

  1. Server ngừng chấp nhận các kết nối mới từ client.
  2. Chờ các câu truy vấn và transaction đang chạy dở dang hoàn tất (hoặc gửi tín hiệu rollback an toàn).
  3. Flush Dirty Pages: Toàn bộ các trang dữ liệu đã chỉnh sửa trong RAM (Dirty Pages) được ghi trọn vẹn xuống đĩa cứng (Tablespace .ibd).
  4. Ghi nhận checkpoint cuối cùng vào Redo Log.
  5. Đóng an toàn tất cả các file handle và giải phóng bộ nhớ.

2. Tác hại của Forced Kill (`kill -9` hoặc End Process trong Task Manager):

Việc ép tắt ngang process khiến các trang dữ liệu trên đĩa và trong log không đồng bộ, buộc MySQL phải kích hoạt quy trình InnoDB Crash Recovery khi khởi động lại, tiêu tốn nhiều thời gian và có nguy cơ hỏng cấu trúc dữ liệu nếu phần cứng gặp sự cố.

Đọc Error Log (`.err`) & Xử lý Trục trặc Khởi động

Chẩn đoán lỗi xung đột cổng, lỗi phân quyền file và Crash Recovery

1. File Error Log của MySQL nằm ở đâu?

Mặc định file error log có đuôi .err nằm trong thư mục datadir (ví dụ: HOSTNAME.err trên Windows hoặc /var/log/mysql/error.log trên Linux). Có thể tra cứu qua câu lệnh:

SHOW VARIABLES LIKE 'log_error';

2. Ba nguyên nhân khởi động thất bại thường gặp nhất:

  • Xung đột cổng mạng (Port Conflict): Cổng 3306 đã bị tiến trình khác chiếm dụng. Error log sẽ ghi: "Do you already have another mysqld server running on port: 3306?".
  • Lỗi quyền truy cập file (Permissions): User hệ điều hành chạy `mysqld` không có quyền đọc/ghi vào thư mục dữ liệu datadir.
  • Lỗi cú pháp file cấu hình: Gõ sai tên option hoặc sai định dạng trong file my.ini / my.cnf.
