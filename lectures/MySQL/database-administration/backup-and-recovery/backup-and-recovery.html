Lesson 03 · Giám sát & Sao lưu

Giám sát Tiến trình & Sao lưu Phục hồi CSDL MySQL

Theo dõi kết nối thời gian thực với SHOW PROCESSLIST, xử lý truy vấn treo với lệnh KILL, thực thi sao lưu toàn diện bằng mysqldump và quy trình phục hồi dữ liệu an toàn.

Chặng: 1/5 Điểm: 0/100
Chặng 1

Giám sát Kết nối & Luồng với `SHOW PROCESSLIST`

Phân tích các trường Id, User, Host, db, Command (Sleep/Query), Time và State

1. Lệnh kiểm tra danh sách tiến trình:

SHOW PROCESSLIST;
SHOW FULL PROCESSLIST; -- Hiển thị trọn vẹn câu lệnh SQL dài ở cột Info

2. Các trường thông tin then chốt:

  • Id: Thread ID đại diện cho kết nối của client. Được dùng làm đối số khi cần ngắt kết nối.
  • Command:
    • Sleep: Kết nối nhàn rỗi, đang chờ câu lệnh tiếp theo từ ứng dụng.
    • Query: Đang thực thi câu lệnh SQL.
  • Time: Số giây luồng đã ở trạng thái hiện tại. Một câu lệnh Query có Time lên tới hàng trăm giây thường là truy vấn bị treo (hung query) hoặc thiếu Index gây Full Table Scan.
  • State: Chi tiết trạng thái (ví dụ: Waiting for table metadata lock, Sending data).
🎯 Checkpoint Chặng 1
Câu 1: Điểm khác biệt quan trọng giữa lệnh `SHOW FULL PROCESSLIST;` và `SHOW PROCESSLIST;` là gì?
Câu 2: Trong kết quả `SHOW PROCESSLIST`, nếu một tiến trình có `Command = 'Sleep'`, điều này có nghĩa là gì?
Chặng 2

Xử lý Truy vấn Treo bằng Lệnh `KILL`

Phân biệt ngắt truy vấn (`KILL QUERY`) và ngắt toàn bộ kết nối (`KILL connection`)

1. Khi nào cần dùng lệnh KILL?

Khi một câu truy vấn chạy quá lâu chiếm dụng 100% CPU, hoặc một giao dịch giữ khóa (lock) khiến hàng loạt ứng dụng khác bị nghẽn (Waiting for lock), người quản trị DBA cần can thiệp ngắt luồng đó bằng lệnh KILL.

2. Hai cấp độ ngắt:

  • Chỉ ngắt câu lệnh SQL đang chạy (KILL QUERY): 
    KILL QUERY 45;
    Tác dụng: Dừng câu query tốn tài nguyên nhưng vẫn giữ nguyên kết nối mạng của client (rất an toàn cho connection pool của ứng dụng backend).
  • Ngắt hoàn toàn kết nối (KILL Connection): 
    KILL 45; -- hoặc: KILL CONNECTION 45;
    Tác dụng: Đóng phiên làm việc và ngắt socket mạng của client đó.
🎯 Checkpoint Chặng 2
Câu 1: Để dừng một câu truy vấn SELECT chạy tốn tài nguyên của thread ID 128 nhưng VẪN GIỮ NGUYÊN kết nối mạng của ứng dụng, DBA nên dùng lệnh nào?
Câu 2: Số định danh truyền vào sau lệnh KILL (ví dụ: `KILL 105;`) được lấy từ cột nào trong bảng kết quả của `SHOW PROCESSLIST`?
Chặng 3

Giới thiệu `mysqldump` & Các Chế độ Sao lưu Cơ bản

Bản chất của Logical Backup, xuất file SQL, sao lưu một DB, nhiều DB và một bảng

1. Bản chất của `mysqldump`:

mysqldump là công cụ sao lưu logic (Logical Backup). Nó đọc dữ liệu từ server và tạo ra file văn bản thuần (.sql) chứa các câu lệnh DROP TABLE IF EXISTS, CREATE TABLE và INSERT INTO để tái tạo lại CSDL.

2. Các cú pháp sao lưu cơ bản trong Command Prompt/Terminal:

# 1. Sao lưu 1 database:
mysqldump -u root -p classicmodels > classicmodels_backup.sql

# 2. Sao lưu riêng 1 bảng cụ thể:
mysqldump -u root -p classicmodels customers > customers_table.sql

# 3. Sao lưu nhiều database:
mysqldump -u root -p --databases db1 db2 > multi_databases.sql

# 4. Sao lưu toàn bộ mọi CSDL trên server:
mysqldump -u root -p --all-databases > full_instance_backup.sql

Câu 1: File đầu ra được tạo bởi công cụ `mysqldump` có định dạng bản chất là gì?
Câu 2: Để chỉ sao lưu DUY NHẤT bảng `employees` trong database `classicmodels`, câu lệnh nào sau đây là ĐÚNG?
Chặng 4

Sao lưu Nâng cao: Schema-only, Data-only & `--single-transaction`

Tùy chọn `--no-data`, `--no-create-info`, `--routines`, `--triggers` và sao lưu không khóa bảng

Các tùy chọn (flags) nâng cao thiết yếu:

  • --no-data (hoặc -d): Schema-only — Chỉ xuất cấu trúc bảng (DDL), không có dòng dữ liệu nào. Rất thích hợp khi muốn tạo database mẫu cho môi trường dev/staging.
  • --no-create-info (hoặc -t): Data-only — Chỉ xuất các câu lệnh INSERT INTO, không xuất CREATE TABLE.
  • --routines (hoặc -R): Sao lưu cả Stored Procedures và Stored Functions.
  • --triggers: Sao lưu các Triggers gắn với bảng.
  • --single-transaction: Quy chuẩn vàng cho InnoDB. Tùy chọn này sử dụng cơ chế đọc cô lập (Snapshot Isolation) để tạo bản sao lưu nhất quán mà không cần khóa bảng (No table lock), cho phép ứng dụng đọc/ghi bình thường trong khi backup.
🎯 Checkpoint Chặng 4
Câu 1: Tùy chọn nào trong `mysqldump` cho phép tạo bản sao lưu nhất quán của cơ sở dữ liệu InnoDB mà KHÔNG làm gián đoạn (khóa bảng) các ứng dụng đang ghi dữ liệu?
Câu 2: Khi cần xuất cấu trúc các bảng của CSDL để bàn giao cho đội phát triển mà TUYỆT ĐỐI KHÔNG chứa bất kỳ dữ liệu khách hàng nào, cờ tùy chọn nào được sử dụng?
Chặng 5

Quy trình Phục hồi (Restore) & Xác minh Toàn vẹn Dữ liệu

Nạp file dump qua toán tử `<`, lệnh `SOURCE` và checklist nghiệm thu sau restore

1. Các cách phục hồi file dump vào MySQL:

  • Cách 1: Sử dụng toán tử chuyển hướng input `<` với client `mysql`: 
    # Tạo database đích nếu chưa có
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS classicmodels_test;"

# Thực thi nạp file dump
mysql -u root -p classicmodels_test < classicmodels_backup.sql
  • Cách 2: Sử dụng lệnh `SOURCE` trong console: 
    USE classicmodels_test;
SOURCE C:/backups/classicmodels_backup.sql;

2. Checklist xác minh sau phục hồi (Post-restore verification):

  • Kiểm tra bảng: SHOW TABLES; để đếm tổng số bảng so với hệ thống nguồn.
  • Kiểm tra số lượng dòng (Row counts): SELECT COUNT(*) FROM customers; để chắc chắn không bị thiếu dữ liệu.
  • Kiểm tra view và routines: SHOW FULL TABLES WHERE Table_type = 'VIEW'; và SHOW PROCEDURE STATUS;.

Câu 1: Trong cửa sổ dòng lệnh Terminal, câu lệnh nào sau đây phục hồi file sao lưu `db_backup.sql` vào cơ sở dữ liệu `app_db`?
Câu 2: Sau khi chạy lệnh phục hồi một database lớn thành công, hành động kiểm tra cơ bản đầu tiên mà DBA cần làm để xác minh sơ bộ dữ liệu là gì?
