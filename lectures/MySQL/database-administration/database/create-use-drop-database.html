Quản lý Vòng đời Database trong MySQL

Nắm vững kỹ thuật tạo lập, chọn database mặc định, xóa CSDL an toàn; cấu hình bảng mã ký tự utf8mb4, collation và danh mục kiểm tra an toàn trong môi trường doanh nghiệp.

Chặng: 1/5 Điểm: 0/100
Chặng 1

Khái niệm Database & Schema trong MySQL

Quan hệ đồng nghĩa giữa Database và Schema, CSDL hiện hành và tên đối tượng đầy đủ

1. Database và Schema trong MySQL là gì?

Khác với một số hệ CSDL như Oracle hay PostgreSQL (nơi Schema là tập hợp các bảng thuộc sở hữu của một User nằm bên trong một Database), trong MySQL hai khái niệm DATABASE và SCHEMA là từ đồng nghĩa hoàn toàn (Synonyms). Hai câu lệnh sau có hiệu lực tương đương 100%:

CREATE DATABASE sales_db;
CREATE SCHEMA sales_db;

2. Tên đối tượng đầy đủ (Fully Qualified Name):

Trong MySQL, một bảng có thể được truy xuất mà không cần chọn database trước bằng cách dùng tên đầy đủ theo cú pháp ten_database.ten_bang:

SELECT * FROM classicmodels.customers;

3. Kiểm tra CSDL hiện hành:

SELECT DATABASE(); -- Trả về NULL nếu phiên làm việc chưa chọn database nào
🎯 Checkpoint Chặng 1
Câu 1: Trong MySQL, nhận định nào sau đây là CHÍNH XÁC về mối quan hệ giữa thuật ngữ `DATABASE` và `SCHEMA`?
Câu 2: Khi vừa kết nối vào MySQL mà chưa thực thi lệnh chọn database, câu lệnh `SELECT DATABASE();` sẽ trả về kết quả gì?
Chặng 2

Lệnh `USE` & Thiết lập CSDL Mặc định cho Session

Phạm vi ảnh hưởng của USE, lỗi kết nối và chuyển đổi database linh hoạt

1. Cú pháp và Bản chất của lệnh USE:

USE classicmodels;
  • Lệnh USE cho MySQL biết rằng tất cả các câu truy vấn không có tiền tố database sau đó sẽ mặc định tìm kiếm các bảng trong database được chỉ định.
  • Phạm vi (Scope): Lệnh USE chỉ tác động đến phiên làm việc (Session) hiện tại của kết nối đó, hoàn toàn không làm ảnh hưởng tới các kết nối khác của người dùng khác trên server.
  • Nếu chỉ định một database không tồn tại, MySQL trả về lỗi: ERROR 1049 (42000): Unknown database 'ten_db'.
🎯 Checkpoint Chặng 2
Câu 1: Khi client A thực hiện câu lệnh `USE sales;`, điều gì xảy ra với kết nối của client B đang làm việc trên cùng một MySQL server?
Câu 2: Nếu một phiên làm việc đang ở trong database `hr`, làm cách nào để truy vấn dữ liệu từ bảng `orders` của database `sales` mà KHÔNG CẦN đổi database mặc định bằng lệnh USE?
Chặng 3

Tạo Database với `CREATE DATABASE`, Charset & Collation

Cú pháp chuẩn, mệnh đề IF NOT EXISTS, chuẩn utf8mb4 và Collation utf8mb4_0900_ai_ci

1. Cú pháp khởi tạo Database tiêu chuẩn:

CREATE DATABASE IF NOT EXISTS ecommerce_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

2. Vì sao phải sử dụng `utf8mb4` thay vì `utf8` (utf8mb3)?

  • Bảng mã utf8 cũ của MySQL thực chất chỉ là utf8mb3 (chỉ hỗ trợ tối đa 3 bytes cho một ký tự), không thể lưu trữ các biểu tượng cảm xúc (Emoji 😀), một số ký tự Hán tự hiếm và các ký tự đặc biệt.
  • utf8mb4 (4 bytes per character) là chuẩn bắt buộc hiện đại, hỗ trợ toàn diện Unicode.

3. Ý nghĩa của Collation `utf8mb4_0900_ai_ci`:

  • 0900: Tuân thủ thuật toán sắp xếp của chuẩn Unicode 9.0.0.
  • ai (Accent-Insensitive): Không phân biệt dấu thanh điệu khi so sánh (ví dụ: 'e' bằng 'é').
  • ci (Case-Insensitive): Không phân biệt chữ hoa chữ thường ('A' bằng 'a').
🎯 Checkpoint Chặng 3
Câu 1: Vì sao trong MySQL hiện đại (từ 8.0 trở lên), chuẩn bảng mã `utf8mb4` được khuyến nghị sử dụng thay thế cho `utf8` (utf8mb3)?
Câu 2: Trong tên Collation `utf8mb4_0900_ai_ci`, hai hậu tố `_ai` và `_ci` có ý nghĩa lần lượt là gì?
Chặng 4

Khám phá Siêu dữ liệu Định nghĩa Database

Lệnh `SHOW CREATE DATABASE` và truy vấn danh mục `INFORMATION_SCHEMA.SCHEMATA`

1. Xem câu lệnh DDL khởi tạo database:

SHOW CREATE DATABASE classicmodels;

Kết quả hiển thị chính xác cú pháp DDL, bao gồm charset và collation đang được áp dụng.

2. Tra cứu toàn diện qua `INFORMATION_SCHEMA.SCHEMATA`:

SELECT SCHEMA_NAME, DEFAULT_CHARACTER_SET_NAME, DEFAULT_COLLATION_NAME
FROM INFORMATION_SCHEMA.SCHEMATA
WHERE SCHEMA_NAME NOT IN ('mysql', 'information_schema', 'performance_schema', 'sys');

Bảng SCHEMATA cho phép lọc, sắp xếp và báo cáo các database tồn tại trên máy chủ.

🎯 Checkpoint Chặng 4
Câu 1: Câu lệnh SQL nào hiển thị chính xác câu lệnh DDL đã được dùng để tạo ra database `classicmodels` kèm theo thiết lập Charset và Collation của nó?
Câu 2: Bảng hệ thống nào trong MySQL lưu trữ danh sách siêu dữ liệu (metadata) của tất cả các database trên máy chủ?
Chặng 5

Xóa Database với `DROP DATABASE` & Checklist An toàn

Hậu quả xóa vật lý trên ổ đĩa, mệnh đề IF EXISTS và các CSDL hệ thống cấm xóa

1. Tác động của câu lệnh `DROP DATABASE`:

DROP DATABASE IF EXISTS test_lab;
  • Xóa vĩnh viễn: Tất cả các tables, views, stored routines, triggers và các file dữ liệu vật lý (thư mục con trong datadir) bị xóa khỏi đĩa cứng. MySQL không có cơ chế Recycle Bin để Undo!

2. Checklist an toàn trước khi thực hiện DROP DATABASE:

  • Xác minh môi trường: Đảm bảo bạn đang kết nối vào máy chủ local/test, không phải production.
  • Thực hiện Backup trước: Luôn chạy mysqldump để có bản dự phòng trước khi drop.
  • Tuyệt đối KHÔNG xóa 4 Database Hệ thống:
    • mysql: Chứa thông tin tài khoản người dùng, phân quyền và dữ liệu quản trị cốt lõi.
    • information_schema: Từ điển dữ liệu siêu dữ liệu ANSI.
    • performance_schema: Thu thập dữ liệu hiệu năng máy chủ.
    • sys: Tập hợp các view hỗ trợ chẩn đoán DBA.
🎯 Checkpoint Chặng 5
Câu 1: Cơ sở dữ liệu nào sau đây là CSDL hệ thống cốt lõi lưu trữ bảng quản lý tài khoản người dùng và phân quyền trong MySQL, TUYỆT ĐỐI KHÔNG ĐƯỢC XÓA?
Câu 2: Vì sao trong các kịch bản tự động hóa hoặc script deploy CSDL, người ta thường viết `DROP DATABASE IF EXISTS db_name;` thay vì chỉ viết `DROP DATABASE db_name;`?
